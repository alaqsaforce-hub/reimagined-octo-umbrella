# v0.6.5 — backup & restore + lint hardening

Base: `project/v061` at v0.6.4. Built and tested on 2026-10-30. No new permissions, no new network calls,
no cloud account.

## 1. Backup & restore (fills the "no backup/export" gap from the v0.5 audit)

The audit's gap list said *"no backup/export"*. VoiceDock stores everything locally and
`allowBackup="false"`, so before this release an uninstalled app meant permanently lost drafts and
knowledge. Now the user can export and re-import their own text.

- **`backup/BackupModels.kt`** (new, pure/JVM-tested) — a readable JSON format:
  `{app, schema, appVersion, exportedAt, drafts[], documents[]}`. Drafts carry raw + formatted text,
  status, language, engine, destination and the segment list. Documents carry title, source metadata
  and their **indexed chunks verbatim** (chunks overlap by design, so they are never re-joined).
- **Secrets are structurally impossible to export.** The model has no field for API keys, IMAP app
  passwords, GitHub tokens, OAuth tokens, the ChatGPT/OpenRouter session or the Keystore blob — they
  live in `SecretStore` and are unreachable from the backup code. `BackupCodecTest` asserts that the
  encoded JSON never contains such a key.
- **Validation instead of trust.** Wrong app id, empty file, non-JSON, `schema` outside 1..1, more than
  5 000 drafts / 5 000 documents / 5 000 chunks per document, or a file over 24 M characters are refused
  or trimmed with a human-readable note. Unknown JSON keys are ignored, so a future version's file can
  still be read.
- **Import merges, never deletes.** A draft is replaced only when the same draft id is present (that is
  the same draft); a knowledge document is skipped when its `contentHash` is already stored; duplicate
  documents inside one file collapse.
- **`backup/BackupManager.kt`** (new) — maps Room entities ↔ backup records and performs the merge.
  Two read-only DAO queries were added (`DraftDao.all()`, `KnowledgeDao.allDocuments()`); **the Room
  schema is unchanged**, so no migration is needed.
- **UI** — Settings → *Backup & restore*: "Save backup" writes through the system
  `CreateDocument("application/json")` picker with a `voicedock-backup-YYYY-MM-DD.json` suggestion;
  "Restore from backup" reads through `OpenDocument`, bounded to 24 M characters, and reports exactly
  how many drafts/documents were added, replaced or skipped. The card shows how many drafts and
  documents exist on the phone.

## 2. Privacy

- New `res/xml/backup_rules.xml` (`android:fullBackupContent`) excludes root/database/sharedpref/file/
  external from Android Auto Backup on **API 26–30**, matching `data_extraction_rules.xml` which only
  applies to API 31+. `allowBackup="false"` already covered this; the rules make it defence in depth.
- `PRIVACY.md` documents exactly what the backup file contains and what it cannot contain.

## 3. Lint / code hardening (0 errors, warnings reduced)

| Finding | Fix |
|---|---|
| `StaticFieldLeak` in `SettingsStore` (static Context) | Store the `SharedPreferences` instance instead of a `Context` — behaviour unchanged, leak gone |
| `StaticFieldLeak` on `VoiceDock.gemini` | Documented `@SuppressLint` with justification: application-scoped singleton built from the application context |
| `ObsoleteSdkInt` ×2 (`SDK_INT >= 26` when minSdk is 26) | Dead checks removed (`A11yDevice`, `InsertAccessibilityService`) |
| `DataExtractionRules` (no API 26–30 equivalent) | Added `android:fullBackupContent="@xml/backup_rules"` |
| `NewApi` ×7 in `RecognizerCatalog` (fixed in the v0.6.4 build) | `@RequiresApi(33)` on the helper |

Remaining warnings are informational or third-party: 14 `UseKtx` style hints, 9 newer-dependency
suggestions, `ChromeOsAbiSupport` (arm64-only by design for whisper.cpp), `UsableSpace` advice in the
Whisper model downloader, and BouncyCastle's own `TrustAllX509TrustManager` inside the vendor jar.

## Not done / not claimed

- Nothing here was run on a phone. The file pickers, the merge against a real database and a real
  round-trip on device are untested (JVM tests cover the format and its validation only).
- Still no encrypted backup. If you want the file itself encrypted with a passphrase, that is a separate
  design (needs a KDF + format version bump), not a silent change.
- `v0.7` work (persistent memory, notification catch-up) is untouched — this release deliberately
  touches no background collection.
