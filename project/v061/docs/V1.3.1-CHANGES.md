# VoiceDock AI v1.3.1 — voice-to-voice surface, the draft card, and calls that stay floating

Release date: 2026-11-01 · versionCode 23 · versionName "1.3.1" · minSdk 26 · target/compile 35

This is the third item of the "platform" request, the one v1.3.0 deliberately left out:

> *"ভয়েস-টু-ভয়েস ChatGPT-এর মতো ইন্টারফেস; ফোনে/হোয়াটসঅ্যাপে কল বললে ডায়াল করে **ফ্লোটিং মোডে** থাকবে;
> মেসেঞ্জার/চ্যাটের উপরে ফ্লোটিং; যা বলেছি তা সাজিয়ে **ড্রাফট দেখাবে**, ‘ঢোকাও’ বললে বসাবে — নয়তো নিজে করব।"*

All three clauses are addressed below. Every claim is backed by a test (`docs/TEST-RESULTS-v1.3.1.md`).

---

## 1. Voice-to-voice, built like a conversation (`ui/screens/VoiceScreen.kt`)

* New **ভয়েস মোড** screen — Home → "🎧 ভয়েস মোড", or say **"ভয়েস মোড খোলো"**, or the bubble can open it.
* One column of turns, the way a chat reads: **your words** in a filled bubble, **what actually happened** in the
  reply bubble under it (✓/✗, the intent, the parse source, the confidence).
* The reply is **not generated copy** — it is the real record from `CommandLog`, the same log the diagnostics
  screen reads. So a turn reads *"কল করা হচ্ছে ✓ (বাবল খোলা থাকছে)"* or *"কল করা যায়নি (অনুমতি বা সিস্টেম বাধা)"*
  because that is what the executor returned, not because a template said so.
* Live transcript while speaking (the existing v0.6 dictation engine), a level-responsive orb (tap = listen /
  tap again = pause), and `নতুন / পরিষ্কার / থামাও`.
* The screen never claims to be a cloud chatbot: the transcript stays on the phone, and the note at the top says
  what the two buttons do.

## 2. The draft card — shown, never auto-inserted (`draft/DraftCore.kt`)

* Any finished dictation becomes a **draft card** inside the floating bubble: title, the composed text, the
  target, and three explicit actions — **ঢোকাও**, **রাখো**, **বাতিল**.
* `DraftCore` is pure and unit-tested:
  * `tidy()` drops a leading wake word ("শাহরুখ, …") and normalises whitespace — **the user's wording is never
    rewritten**, it is a draft, not a paraphrase. Capped at 1,500 characters.
  * `plan()` states the route honestly: **Accessibility** ("কার্সর যে ঘরে আছে সেখানে বসবে") or **Clipboard**
    ("Accessibility চালু নেই — লেখাটা কপি হবে, আপনি পেস্ট করুন"). A target is named **only when it is known**.
  * `requiresExplicitInsert` is `true` as a constant, so no future call site can quietly start auto-inserting.
* Insertion reuses the audited path (`TextInserter`: accessibility → honest clipboard fallback with the real
  `InsertResult` message) and marks the draft inserted in Draft history.
* **By voice too, but only on an exact request:** "ঢোকাও" / "বসাও" / "লিখে দাও" / "insert" → `draft.insert`;
  "খসড়া বাতিল" / "discard draft" → `draft.discard`. A sentence that merely mentions inserting
  ("ওখানে বসাও না, পরে করব") does **not** fire — that is a test, not a hope.

## 3. Calls stay in floating mode

* After a placed call the bubble is **kept open** and says so: *"বাবল খোলা থাকছে — কল চলাকালীনও ‘কেটে দাও’ বা অন্য
  কমান্ড দিতে পারবেন।"* The SIM-pinned path and the default path both do this.
* There is no auto-hide timer in the service (verified), so nothing closes the bubble mid-call; the note makes the
  behaviour visible instead of accidental.
* A WhatsApp/Messenger *call* still cannot be placed by any public API — unchanged from v0.9: the assistant
  answers/declines through the app's own notification buttons and states what it did.

## 4. Command layer

* Three new intents: `draft.insert`, `draft.discard`, `voice.open` — registered, available, non-destructive
  (so no confirmation card can appear for them, which is itself asserted by a test).
* The offline parser puts the draft rules **first**, before the app-open rules, because "বসাও" would otherwise
  look like "open something". Three regression assertions guard the older grammars (app open, call, search, SIM).

## Not in this build (stated, not hidden)

* Nothing is inserted into a **password/secure** field — that check stays where it was (`InsertResult.SECURE_FIELD`).
* Instagram/Facebook/YouTube content summaries, calendar, and silent send in apps without a notification action
  remain later work (`ROADMAP-v1.2-to-v1.4.md`).
* The voice screen does not stream a cloud model's audio: replies are the app's own TTS per mode (v1.1.0), and the
  turns shown are command outcomes. Anything else would be a different product than the one described here.
