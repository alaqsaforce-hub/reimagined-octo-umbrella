# VoiceDock AI v1.4.1 — MCP tool policy (ask only when it matters)

**Date:** 2026-11-01 · **APK:** `artifacts/VoiceDock-AI-v1.4.1-debug.apk` (vc 28, 1.4.1)

v1.4.0 confirmed **every** MCP tool run, because the app had no idea what a tool would do. That was safe and
annoying. v1.4.1 makes the question proportional — without ever guessing.

## The rule (one line)

> A tool runs without a card **only** if the server itself marks it `readOnlyHint: true` and *not*
> `destructiveHint: true`. A write tool confirms. A tool that says nothing about itself confirms too —
> **silence is not permission.**

| Server annotation | What happens | Example |
|---|---|---|
| `readOnlyHint: true`, no destructive hint | runs straight through | `get_file_contents`, `search_code`, `list_commits` |
| `destructiveHint: true` | confirmation card first | `create_or_update_file`, `push_files`, `merge_pull_request` |
| no annotations / unknown tool name | confirmation card first | anything a server forgot to describe |

## Built

- **`mcp/McpCore.kt`** — reads `annotations` (`readOnlyHint`, `destructiveHint`, `title`), exposes
  `needsConfirm` per tool, `policyLabel()` for the UI ("পড়া-মাত্র" / "ধ্বংসকারী — আগে জিজ্ঞেস করবে" /
  "অজানা — আগে জিজ্ঞেস করবে"), and `serverInfo()` so the handshake's `serverInfo.name/version` can be shown.
  `toolsAnswer` now prints **how many tools are read-only** and the policy next to every name.
- **`mcp/McpTools.kt`** (new) — an in-memory, 10-minute snapshot of the last `tools/list`, so the *pipeline*
  (which runs before any network call) can decide whether to confirm. Expired or missing → confirm. Nothing is
  written to disk; a restart asks once more. Longest-name matching is shared with the executor, so the card the
  user sees and the tool that runs can never be two different things.
- **`CommandPipeline.decide()`** — gained an injectable `needsConfirm(intent, spec)`; the default keeps every
  other intent exactly as before, so this change cannot loosen any existing safety rule.
- **Executor** — remembers the tool list after `mcp.tools` *and* after a successful run, so the second
  `mcp.run` of the same tool also skips a confirmation it already earned.
- **Settings → MCP** — one-tap **"GitHub MCP যোগ করুন"** preset (`https://api.githubcopilot.com/mcp/`, token in
  its own `mcp_token_github` slot, not duplicated on re-tap), the policy written on the screen in Bengali, and
  the test result now names the server and marks each tool's policy.

## What this deliberately still does **not** do

- No automatic choice of tool from a vague sentence: the user still names the tool (`"mcp দিয়ে search_code চালাও …"`),
  and an unknown name answers with the real list.
- No per-tool allowlist UI yet (read-only tools are already frictionless; a per-tool "never ask" switch would be
  the next step, and it must only ever be offered for `readOnlyHint` tools).
- The GitHub preset is an address, not a guarantee: if GitHub changes that endpoint, the honest failure sentence
  appears instead of a fake success.
