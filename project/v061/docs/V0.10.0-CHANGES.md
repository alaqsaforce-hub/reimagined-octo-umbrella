## 1. Media — "পরের গান", "গান থামাও", "গান চালাও"

Android has no public "media player" API. The route that actually covers every player is
`MediaSessionManager.getActiveSessions()` — the same notification-listener access v0.8.0 already asks for.
No package names, no per-app special cases: Spotify, YouTube Music, podcasts, the stock player and
browsers all expose a `MediaSession`.

| You say | Action sent |
|---|---|
| "গান চালাও" · "play music" | `play()` |
| "গান থামাও" · "pause the music" | `pause()` |
| "পরের গান" · "next song" | `skipToNext()` |
| "আগের গান" · "previous track" | `skipToPrevious()` |
| "গান বন্ধ করো" · "stop the music" | `stop()` |
| "গান" (vague) | **asks** which of four actions — never guesses play vs pause |

Which session: the one that is playing, else the one publishing a title, else the first
(`MediaPick.best`, unit-tested). Three honest failures, each with its own sentence:

* `no_access` — notification access is off → button to fix it in Settings → কমান্ড;
* `no_player` — nothing is playing → "আগে গান চালু করুন";
* already in the requested state → said as such instead of a fake "✓".

**Pause ≠ Stop** is enforced in code *and* in a test: pausing keeps the queue, stopping ends it.

## 2. Chains — "শেষ যে মেসেজ দিয়েছে তাকে ফোন করো"

Not a new intent. The sentence is still an ordinary `call.place` / `msg.reply`; what the chain adds is
resolving the *recipient* from the notification log before anything is confirmed:

```
"call the last person who messaged me"
  → ChainResolver (pronoun detected) → newest sender from the notification log → "রহিম"
  → ordinary contact→number resolution → confirmation card showing "রহিম" + the number
```

Nothing is invented: no captured messages → "আজ কারও মেসেজ পাওয়া যায়নি"; no notification access →
says so and offers the setting. A named person ("রহিমকে ফোন করো") is never replaced by the chain —
`ChainResolver.isChain` only fires on a pronoun.

## 3. Undo — the ↩ chip in the bubble and the word "আনডু"

One step, 60 seconds, and only where the reversal is real:

| Action | Undo does |
|---|---|
| "মনে রাখো …" | deletes the row that was just written |
| media play/pause | sends the inverse transport command |
| media next | **no undo offered** — the queue position is gone |
| call / message / app launch | **no undo offered** — and the button is absent, not dead |

`UndoLog` (single slot, TTL, clock injectable) is pure and tested; the revert itself lives in the service
and is logged (`undo:memory_add`, `undo:media`).

## 4. Room migration (the v0.9.0 deferral)

The JSON stores are gone from the hot path: `memory_entries` and `notif_entries` are Room tables at
**schema v3**, with an explicit `MIGRATION_2_3` whose DDL is copied from the generated
`app/schemas/…/3.json` (that file is committed).

* `LegacyImport` copies `voice_memory.json` / `notifications.json` into Room **once**, in the thread that
  opens the database. If it throws, the flag stays unset and the JSON files stay untouched — a failed
  import cannot lose a memory. On success the JSON files are **renamed** `*.imported`, not deleted.
* `MemoryStore` / `NotifStore` keep their old constructors (JSON path) and gain an optional `dao`; the app
  always passes one. Same contract either way: newest first, blank ignored, capped at 300 / 400.
* The upgrade is tested against a **real v2 database** built from the v2 schema (same DDL, same identity
  hash `0cdc7fe3…`): after the upgrade the old draft is still readable and both new tables work.

## 5. Assistant role (long-press home)

Settings → কমান্ড → **ডিজিটাল অ্যাসিস্ট্যান্ট**: status line + a button that opens Android's
*Default apps → Digital assistant* screen (`ROLE_ASSISTANT`, Android 10+). `MainActivity` now answers
`ACTION_ASSIST` / `ACTION_VOICE_COMMAND` by starting the same bubble as the floating icon.
The setting replaces any other assistant (e.g. Google) and Android's own screen is where it is switched
back — the app does not silently steal the gesture.

## Fixed on the way

* **"রহিমকে ফোন করো"** produced the contact `"ো"` — the verb "করো" left its vowel sign behind after the
  trigger "ফোন কর". Now a fragment with no letter/digit of its own falls back to the part *before* the verb.
* "গান থামাও" was matched by both the pause and the stop keyword lists (stop won, checked first) — pause
  now owns it.
* The parser writes actions as closed tokens (`next`, `play`), so `MediaText.action` accepts those tokens
  verbatim — a model that answers with `"next"` is understood too.
