# VoiceDock AI v1.4.0 — MCP client (the agent's hands)

**Date:** 2026-11-01 · **APK:** `artifacts/VoiceDock-AI-v1.4.0-debug.apk` (vc 27, 1.4.0)

The v1.4 layer starts where the roadmap said it would: the agent gets **hands** in the form of MCP
(Model Context Protocol) tool servers the user adds themselves.

## What MCP is here, in one paragraph

A server speaks JSON-RPC 2.0 over HTTP and says "these are my tools". VoiceDock lists them and runs one when
the user asks for it by name. There is no bundled server, no hidden endpoint, no default token — an empty
list is the normal starting state, and the app says so instead of pretending.

## Built

### `mcp/McpCore.kt` — every decision, no I/O (pure, fully unit-tested)

| Piece | Rule |
|---|---|
| `McpServer(id, name, url, enabled, tokenName)` | `@Serializable`, stored in `AppSettings`; the token itself lives in the Keystore-backed `SecretStore` under `mcp_token_<id>` |
| `sanitize(list)` | keeps only `http(s)://` URLs, trims, de-dupes by URL, caps at 8, and **fills a blank name from the URL** so Settings never shows an empty row |
| `serverFrom(name, url)` | adds `https://` when the user forgets it, rejects junk (`ftp://`, spaces, too short) |
| `redact(url)` | drops `user:pass@` and every query parameter except harmless ones — a shown URL never carries a secret |
| `initializeBody` / `initializedNotification` / `toolsListBody` / `toolsCallBody` | exactly the spec's messages; `protocolVersion 2025-06-18`, `clientInfo VoiceDock AI` |
| `parseRpc(body)` | reads **plain JSON and SSE** (`data:` lines, notifications ignored) → `RpcReply(id, result, errorCode, errorMessage)` |
| `parseTools(reply, server)` | name is mandatory (nameless tools dropped), keeps `properties` + `required` from `inputSchema` |
| `argumentsFor(tool, spoken)` | dictated JSON → validated; `k=v` pairs → those keys; otherwise the sentence goes into the tool's **first required** property, else `query/q/text/input`, else `{}` — **never a made-up key** |
| `parseToolResult(reply)` | concatenates `text` content; non-text parts are counted honestly ("আরও ২টি অংশ … ছবি/ফাইল"); `isError` is preserved; a transport error is **never** dressed up as an answer |
| `failure(reason)` | one sentence per `no_url`, `nonet`, `timeout`, `http_401/403/404`, `rpc_*` |

### `mcp/McpClient.kt` — the network half

- POST per exchange, `Accept: application/json, text/event-stream`, `MCP-Protocol-Version: 2025-06-18`,
  session id from `Mcp-Session-Id` remembered per server and echoed (cleared on 401/403).
- `connect(server, token)` = handshake + `notifications/initialized` + `tools/list`; **never cached**, so the
  list always describes the server as it is now.
- `call(server, tool, args, token)` = one `tools/call`, **no automatic retry** (a tool may have side effects;
  retrying has to be the user's decision).
- Timeouts: 12 s connect / 45 s read / 60 s call. Bearer token is sent only if one is stored.

### Commands

| Sentence | Intent | Confirm? |
|---|---|---|
| "MCP টুল দেখাও" / "what MCP tools do you have" | `mcp.tools` | no |
| "mcp দিয়ে read_file চালাও path=/sdcard/a.txt" | `mcp.run` | **yes, always** |

- `mcp.run` only ever calls a tool the server *just listed*; an unknown name produces the list of real ones.
- Confirmation is unconditional (not confidence-gated) because the app cannot know what a third-party tool
  does; Fast Mode can still opt in per the existing per-intent rule.

### Settings → MCP (new section)

Add a server (name + address + optional token), enable/disable, **"টুল দেখুন"** (real handshake, shows the
tool count and names or the exact failure), remove. The screen states plainly that a tool server can do
anything it is allowed to do, and that VoiceDock asks before running a tool.

## Deliberately not in this release

- No bundled/starter server, no OAuth flow for remote MCP servers (bearer token only).
- No resources/prompts/sampling — tools only.
- No tool-call history or background tool runs: everything is one request, in the foreground, on demand.
- SSH/VPS and goal→plan agents remain for the next increments (roadmap v1.4.x).
