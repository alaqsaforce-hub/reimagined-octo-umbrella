# VoiceDock AI — v0.9.0 "handles my calls" (versionCode 16)

Phase 3 of the Jarvis plan. Adds four runtime permissions, all requested by you from
**Settings → কমান্ড → কল** — never automatically.

## What you can do now

Dictate, then **hold ⏎**:

| You say | What happens |
|---|---|
| "মাকে ফোন দাও" / "call Rahim" | the contact is resolved **before** a confirmation card that shows the name **and the number**; on yes the call is placed |
| a number itself: "০১৭১১১১১১১১ নম্বরে ফোন কর" | dialled directly (Bengali digits are mapped 1:1, so it is a real number) |
| "ধরো" / "রিং হচ্ছে" / "answer it" | answers the ringing call, no confirmation (a card would outlive the ring) |
| "কেটে দাও" / "decline" | declines it, with a confirmation first |

### The answer chain, and why it matters

```
1. TelecomManager.acceptRingingCall()          needs ANSWER_PHONE_CALLS  → strategy "telecom"
2. the ringing notification's own Answer button                        → strategy "notification_action"
   (this is also the ONLY way to answer a WhatsApp/Telegram call —
    those apps expose no call API at all)
3. neither works → "কল ধরতে পারিনি … নিজে ধরুন"                          → no fake success, ever
```

Every outcome is logged with the strategy that ran (`place:telecom`, `answer:notification_action`,
`decline:none`), and Settings → কমান্ড shows the same in the command log — so if your phone's OEM
blocks route 1 you can see that route 2 covered it, instead of guessing.

Placing a call without `CALL_PHONE` does something useful rather than failing: it opens the dialer
with the number already typed, and says so.

## Permissions (new)

| Permission | Needed for | If refused |
|---|---|---|
| `CALL_PHONE` | placing the call | dialer opens prefilled, stated plainly |
| `ANSWER_PHONE_CALLS` | answer / decline via the system API | falls back to the notification button |
| `READ_PHONE_STATE` | call state during the attempt | chain still works |
| `READ_CONTACTS` | "মাকে ফোন দাও" → number | you can still speak the number; the app asks for it |

Optional: **default dialer** button (API 29+) — only if you want it; the app works without it and never
nags.

## Deliberate deviation from the plan

The plan promised to move memory + the notification log into **Room** in this version. I did **not**:
the two JSON stores work, and a Room schema bump on an existing install without a device to test the
migration risks the user's saved drafts. Rooms matter when there is something to query — v0.10 (media +
command chains) will be the moment, and it will ship with a tested `Migration` object rather than an
untested one. Recorded here so the changelog stays truthful.

## Test on the phone (6 checks)

1. Settings → কমান্ড → কল → **অনুমতি দিন** → grant all four → the row must read "✓ সব দেওয়া আছে".
2. "মাকে ফোন দাও" → confirmation card with **name and number** → cancel once (nothing dials).
3. Say yes → the call is placed; the bubble says "…কল করা হচ্ছে ✓" and the log shows `place:telecom`.
4. Get someone to call you → "ধরো" → answered; note which strategy appears in the log.
5. While ringing, "কেটে দাও" → confirmation → declined.
6. Ask a friend to call you on **WhatsApp** → "ধরো" → the notification-button route answers it (or the
   bubble honestly says it could not — that is the expected behaviour on some WhatsApp versions).
