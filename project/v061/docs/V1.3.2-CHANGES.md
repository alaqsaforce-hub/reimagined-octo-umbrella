# VoiceDock AI v1.3.2 — content summaries: one chat's roll-up, and a YouTube link that tells the truth

Release date: 2026-11-01 · versionCode 24 · versionName "1.3.2" · minSdk 26 · target/compile 35

The two summary features that were carried over from the v1.3 plan, both built so that the *gap* is part of
the answer: the phone never invents a message or a caption it did not receive.

## 1. One chat's roll-up ("রহিমের মেসেজের সারমর্ম")

* New pure core `notify/ChatRollup.kt` (sibling of the v0.8 `Digest`): groups the notification log **per
  conversation** (`sender + package`), keeps the last 8 readable messages, counts everything, and remembers
  whether *any* notification arrived with the text hidden.
* New intent **`msg.thread`** — "রহিমের মেসেজের সারমর্ম বলো", "রহিমের সাথে কী কথা হলো", "summary of chat with
  Rahim". The person is what is left after the "summarise this chat" words are removed; a day word
  (আজকের / সব / আমার / my) is **not** a person, so "আজকের মেসেজের সারমর্ম" stays the existing **day digest**.
* The answer is deterministic and offline:
  * `রহিম — ৩টা মেসেজ (WhatsApp)` then the last few messages as bullets;
  * when the app hid the text: *"লেখা দেখা যাচ্ছে না — অ্যাপটি নোটিফিকেশনে মেসেজের লেখা দেখায়নি, তাই সারমর্ম
    বানানো হয়নি।"* — no filler, no model guessing;
  * if only *some* were hidden, the answer says so in one line ("কয়েকটা নোটিফিকেশনে লেখা ছিল না");
  * if Direct Reply is possible, it tells the user how to reply ("রহিমকে বলো …").
* A model is only used to **add** a summary when 3+ readable messages exist; its answer is shown with
  `(উৎস: N টা নোটিফিকেশন — অ্যাপ নিজে which দেখিয়েছে)`, and the prompt itself forbids inventing missing text
  ("যা লেখা নেই তা বানিয়ে বলো না" / "Never invent text that is not shown").

## 2. YouTube link summary ("এই লিংকের সারমর্ম")

* New `summaries/YtSummary.kt`, split the same way as every other feature in this project:
  * **pure** `YtSummaryCore` — recognises `watch?v=`, `youtu.be/`, `/shorts/`, `/embed/`, `/live/` and a bare
    11-character id; reads the page's Open Graph / `itemprop` / `ytInitialPlayerResponse` metadata
    (title, channel, description, duration incl. `PT1H2M3S`); builds the sentence.
  * **network** `YtSummary.fetch(id)` — one GET, one honest failure code (`consent`, `http`, `parse`).
* The answer **always** ends with the honest line:
  *"ক্যাপশন (সাবটাইটেল) পড়া যায়নি — শিরোনাম ও বিবরণ থেকেই সারমর্ম দেওয়া হলো।"*
  Reading captions needs the YouTube app's transcript panel, i.e. the accessibility pass — it is not pretended
  here, and no third-party proxy is assumed.
* With an AI provider configured, the description is summarised in 3 sentences from that text only (the prompt
  says so explicitly); without one, the description itself is shown, trimmed.
* A consent wall or an empty page is a **failure with a reason**, never a fabricated title.

## Command layer

* Two new intents — `msg.thread` (needs a contact), `yt.summary` (needs a query/link) — registered, available,
  non-destructive (a test asserts none of them can pop a confirmation card).
* Ordering matters and is guarded by tests: the YouTube **link** rule runs before the YouTube **search** rule,
  and the chat rule runs before neither the day digest nor "read my messages", all of which keep working:
  `ইউটিউবে রবীন্দ্রসংগীত খোঁজো` → `yt.search`, `আজকের মেসেজের সারমর্ম` → `msg.digest`,
  `শেষ মেসেজগুলো পড়ো` → `msg.read`.

## Honest limits (unchanged and stated in-app)

* WhatsApp/Telegram/etc. content is only what the app put in its notification — no WhatsApp API exists.
* Captions are not read; the accessibility pass for the transcript panel and for silent send is still later work.
* Nothing here uploads the notification log: the sum-summary path is local, and the model path sends only the
  message lines the user asked about, to the provider the user configured.
