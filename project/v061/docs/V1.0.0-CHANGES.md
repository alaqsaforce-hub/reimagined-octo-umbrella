# v1.0.0 — "শাহরুখ" (the wake word), the guide, and the polish

Phase 5 (final) of `JARVIS-UPGRADE-PLAN.md`. The assistant now has **three entry points** and a first run
that explains itself.

---

## 1. The wake word: **"শাহরুখ" / "Shahrukh"**

Named after the actor, as asked. Say it and the bubble opens and starts listening; say it with the command
in the same breath ("শাহরুখ, হোয়াটসঅ্যাপ খোলো") and the command runs straight away.

**How it works, honestly:** `hotword/HotwordService` is an opt-in **microphone foreground service** that
runs the phone's own speech recogniser in a loop and compares every partial result with `WakePhrase`.
There is no cloud, no always-on audio file, no custom wake-word model: the recogniser belongs to the
phone's speech service, so accuracy and battery cost are that service's.

| Matching rule | Example |
|---|---|
| accepted spellings (Bangla + Latin) | শাহরুখ · শাহরুখ খান · শাহ রুখ · শারুক · শাহরুক · shahrukh · shah rukh · shahrukh khan · sharukh · sahrukh |
| punctuation / case / Bengali digits ignored | "শাহরুখ!" ✓ · "SHAHRUKH" ✓ |
| one edit tolerated (recognisers mishear names) | শাহরখ ✓ · shahruh ✓ |
| never a different word | শাহরুখের সিনেমা ✗ · শাহ ✗ · "what is the weather" ✗ |

The last row is the important one: a false positive means the assistant listens to your conversations.
`WakePhrase` enforces a **word boundary** (the next character may not be a letter *or a Bengali vowel
sign*), which is what rejects the possessive "শাহরুখের".

**When it may listen** (`HotwordGate`, pure and tested):

* off by default (`hotwordEnabled = false`) — an always-available microphone is the user's decision;
* by default only while the **screen is on**; listening with the screen off is a **second, separate**
  opt-in (`hotwordAlwaysOn`), and the settings screen then offers the battery-optimisation exemption,
  because Android otherwise kills the service within minutes;
* **never while VoiceDock is dictating** — the microphone is handed over, not shared. On a wake the
  recogniser is destroyed, a short buzz confirms, the assistant opens the bubble, and the listener comes
  back as soon as dictation lets go of the microphone (it polls instead of guessing);
* the notification says *why* it is not listening (permission / screen off / dictation), so silence is
  never mistaken for "it is broken".

## 2. Three entry points

| Entry | How |
|---|---|
| Floating bubble | tap the icon in any app (v0.6) |
| Digital assistant | long-press home / assist gesture (`ROLE_ASSISTANT`, v0.10) |
| Wake word | say "শাহরুখ" (new) |

All three end in the same place: the small bubble, mic on, nothing inserted without ⏎.

## 3. First-run guide (`OnboardingScreen`)

Shown once on first launch, and reopenable from Settings → শুরুর গাইড. Six steps, each with **what it is
for** and its true status: overlay bubble · microphone · notification access · calls & contacts ·
wake word · digital assistant. Every step is skippable, "পরে করবো" always leaves, and a step that is not
granted says which commands will not work instead of silently failing later.

## 4. Polish

* Settings → কমান্ড → **‘শাহরুখ’ ওয়েক-ওয়ার্ড**: status line, listen switch, screen-off opt-in, battery
  button, start/stop, and the privacy sentence.
* The wake word appears in the guide, the settings and the notification — one source of truth
  (`WakePhrase.BN` / `WakePhrase.EN`), asserted in a test so the name cannot drift.
* New permissions: `VIBRATE` (the wake buzz) and `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` (only reachable
  from the screen-off opt-in; lint flags it as a Play-policy risk — noted for a store release).

## Fixed during this version (all caught by tests/lint, not by luck)

1. **Normalisation destroyed Bengali vowel signs** — `"শাহরুখ"` became `"শ হর খ"`, so the wake word could
   never match. Combining marks (Mn/Mc) are now preserved.
2. The **possessive slipped through** the fuzzy path ("শাহরুখের" is two edits away, not one) — the fuzzy
   comparison now runs on the raw word with its marks, not on the letters alone.
3. The letters-only length threshold (`>= 5`) made the fuzzy path **dead code for Bengali**, where the wake
   word has only four letters once its vowel signs are dropped.
4. `startListening` on a null recogniser (a phone with no speech service) — now a named failure with backoff.
5. Lint: `RoleManager` used outside an API-29 guard; three obsolete `SDK_INT` checks cleaned up.

## Not verified (no device — this one matters)

The wake word itself: whether *your* phone's recogniser hears "শাহরুখ" reliably in a quiet room, in a
pocket, and with Bengali vs English as the recognition language; the battery cost of the always-on mode;
and whether the OS keeps the microphone service alive on your OEM. 9 manual checks in
`MANUAL-TESTS-v0.6.md` § v1.0.0 — checks 1–4 decide whether the wake word is usable for you at all.

**Deferred, on purpose:** C9 (voice-fingerprint gate) and C10 (TTS reads messages) from the plan. C9 cannot
be verified without a device (a wrong threshold either locks the user out or lets anyone in), and C10 is
better built on the v0.8 notification log once the wake word is proven. Both stay in `PROGRESS.md`.
