# VoiceDock AI — v0.6.6 (versionCode 12)

**Theme: the tap no longer opens a panel. Tap = microphone on, and a bubble that grows with your text.**

v0.6.5 was tested on a real device and failed its purpose: tapping the floating icon opened a
full-width sheet that covered roughly two thirds of the screen and took the input focus away from the
message box it was supposed to fill. v0.6.6 replaces that first step completely. No new agent
features were added in this build; the existing behaviour was only re-wired.

---

## 1. Tap behaviour, rewritten

| | v0.6.5 (rejected) | v0.6.6 |
|---|---|---|
| Short tap | Full-width bottom panel (`AssistantBubble`), focusable, ~65 % of height, covering 2/3 of the display | Microphone turns on, small dictation bubble appears next to the floating icon |
| Window flags | Focusable → the app underneath lost its cursor | `FLAG_NOT_FOCUSABLE` + `FLAG_NOT_TOUCH_MODAL` + `FLAG_LAYOUT_NO_LIMITS` → the app underneath keeps the cursor and the keyboard state |
| Window size | `MATCH_PARENT` width, fixed tall height | `WRAP_CONTENT` × `WRAP_CONTENT`, max 68 % of the screen width, text capped at 20 % of the screen height |
| Second tap | Closed the panel | Closes the bubble (text is never thrown away — every finished sentence is already saved as a draft) |
| Long press | — | Keeps the old contextual panel (agent chat, drafts, settings) reachable as an optional path |

`AssistantOverlayService.onBubbleTap()` is the new entry point. `activate()` still exists and is now
reachable only by long-pressing the icon, so the previous flow is preserved without being in the way.
The floating icon also changes colour while dictating (red = listening, green = text ready), so the
state is visible without opening anything.

## 2. The bubble grows with the text — and only with the text

New file: `overlay/DictationBubble.kt` (+ `DictationBubbleState` in `overlay/AssistantUi.kt`).

* Width: `widthIn(min = 170.dp, max = 68 % screen width)` — never full width.
* Height: driven by the amount of text. One short sentence gives a two-line bubble; a paragraph
  gives a taller one. A hard cap of 20 % of the screen height keeps the text scrollable past that
  point, so the bubble can never grow into a panel.
* Font size is **not** a size input: the bubble is sized by its content, and the text style is fixed,
  so a different system font scale enlarges the glyphs only up to the same caps.
* A live status dot (red while listening, green when text is ready) and a three-word status label sit
  on the top row, not a title bar.

## 3. Three separate small corner actions (the functions the app exists for)

All of them are 32 dp mini actions on the bottom row — nothing auto-inserts, nothing is hidden:

| Icon | Action | What it does |
|---|---|---|
| ⏎ (filled, bottom-right) | **Insert / send** | `TextInserter.insert(...)` into the focused field of the app underneath (WhatsApp and every other editable field). Falls back to the clipboard with a toast when Accessibility is off or no field is focused. Password and finance-app fields are still refused. |
| ✨ | **Tidy up / regenerate** ("সাজিয়ে দাও") | `AiFormatter.format(..., FormatStyle)` re-writes the recognised text in place (Clean / Message per Settings). The untouched recognition stays on device as the draft, and the bubble says when the AI request failed so the text is never silently lost. |
| 💬 | **Ask the agent** | Sends the text to the configured model and shows the answer *inside the same small bubble* (capped at 22 % of the screen height). The answer is never inserted anywhere. |
| 📋 | Copy | Copies the current text (or the answer, when one is shown). |
| ✕ | Close | Removes the bubble and stops the microphone. |

The microphone is stopped before an insert, and the bubble window is removed first, so the host app
regains input focus before the text is placed at its cursor.

## 4. Safety and privacy behaviour kept

* Secret-like text (codes, PINs, card numbers) is refused before being sent to any AI provider —
  same `SecretDetector` guard as before.
* Insert still goes through `InsertAccessibilityService.insertIntoFocused`, which requires the
  expected package, a real `FOCUS_INPUT` editable node, and refuses password/finance fields.
* Nothing is uploaded anywhere except the explicit ✨ / 💬 actions, which use the user's own key.

## 5. What is *not* in this build

The screen-reading agent commands (open WhatsApp by voice, "summarise today's messages",
"reply to the people who messaged me", music control) are **not** implemented yet. They remain the
next planned increment and are listed here so the changelog does not over-claim. Nothing about them
was added or half-wired in v0.6.6.
