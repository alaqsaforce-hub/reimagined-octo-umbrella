## 1. Scheduled messages

Say it, walk away, and the phone does what it can — and says which of those things it did.

* **"সন্ধ্যা ৭টায় রহিমকে বলো আমি কাল আসব"** → `msg.schedule` (contact + text + time, parsed offline).
* **"রাতে রহিমকে বলো …"** → "রাতে" alone now means **রাত ৯টা** (see §3), and the confirmation always prints
  the resolved clock time, so the convention is never hidden.
* A message job is stored in the **same** `reminders` row that v1.2.0 introduced, now with
  `kind = 'message'` and `target = 'রহিম'` (Room **v5**, explicit `MIGRATION_4_5` with DEFAULTs, so every
  existing reminder keeps working and becomes `kind='reminder'`).
* It survives a reboot, is listed in Settings → রিমাইন্ডার as `আজ সন্ধ্যা ৭:০০ → রহিম` with the body under it,
  and can be cancelled there.

### The honest part

Android gives a normal app exactly three routes into someone's chat. `MessageJobCore.plan` picks one **before**
the moment arrives, the confirmation says which one, and the fired notification repeats it:

| Route | When | What the app says |
|---|---|---|
| **Direct Reply** (`RemoteReply`, the v0.8 path) | that app's notification is live *and* offers a reply action | "নোটিফিকেশনের ভেতর দিয়েই চুপচাপ পাঠিয়ে দেব" → at fire time "✓ রহিম কে পাঠানো হয়েছে" |
| **Open the chat** (`wa.me/<number>?text=…`) | no live notification, but the contact resolves to a number | "চ্যাট খুলে লেখাটা বসিয়ে দেব — ‘পাঠাও’ চাপতে হবে" → the notification's tap opens the pre-filled chat |
| **Nothing** | neither is possible | "এই মুহূর্তে পাঠানোর কোনো পথ নেই" → at fire time "পাঠানো যায়নি — নিজে পাঠান" |

So the app **never claims a send that did not happen**, and never silently drops the message. No `SEND_SMS`
permission was added: an SMS that the user did not see being sent is not a feature worth a Play-policy
restriction, and WhatsApp is where these messages actually go.

## 2. Internet search — the user's own provider

* **Brave** (`X-Subscription-Token`) and **Tavily** (`Bearer`, POST JSON) with the user's key, stored in the
  same Keystore-encrypted `SecretStore` as the AI keys; **SearxNG** for a server the user runs
  (`192.168.0.4:8888` is accepted without the scheme, exactly like the local-model address).
* Nothing is scraped and nothing is proxied through a server of ours — Google/Bing forbid it and a scraper
  breaks every other week.
* Answer: the top 5 snippets go to the AI router (free-first) for a 3–4 sentence summary, then **the sources
  are listed** with links. If no AI provider is configured, the snippets themselves are shown.
* **No provider configured is not an error**: the browser opens with the query and the answer says what to add
  in Settings → সার্চ to get a summary too.
* **"ইউটিউবে রবীন্দ্রসংগীত খোঁজো"** → the YouTube search intent (`vnd.youtube://results?…`, browser fallback).
  Honest limit kept in the answer: *"প্রথম ভিডিওতে চাপ দিন"* — picking the first result needs the
  accessibility pass planned for v1.3.

Both new commands are decided by the existing safety pipeline: a search executes immediately, a scheduled
message **confirms once** (a sent message cannot be taken back).

## 3. One grammar rule

A bare period word now resolves to that period's usual hour: **ভোর ৫টা · সকাল ৯টা · দুপুর ১টা · বিকাল ৪টা ·
সন্ধ্যা ৭টা · রাত ৯টা**. Before, "রাতে মনে করিয়ে দাও" asked for a time; now it schedules 21:00 and says so.
A sentence with no day, period, clock or relative phrase still returns nothing (no silent guess).

## 4. What is still not here

* Accessibility automation of an open chat (silent send without a live notification) — v1.3.
* Choose-the-first-video for YouTube — v1.3, together with the accessibility pass.
* Calendar, social summaries, MCP, VPS/SSH — v1.3 / v1.4 as written in `ROADMAP-v1.2-to-v1.4.md`.
