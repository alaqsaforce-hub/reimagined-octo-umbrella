# VoiceDock AI v1.3.0 — device access, chat instances, Termux, and the background task board

Release date: 2026-11-01 · versionCode 22 · versionName "1.3.0" · minSdk 26 · target/compile 35

This release is the first half of the "platform" request. The user's own order was explicit:

1. **device access first** — two active SIMs, own numbers, several WhatsApp instances, caller identity and
   "is the name saved in my contacts", answer/decline knowing who it is, plus Termux / proot-Ubuntu / OpenCode;
2. **a task board** the user can add tasks to, which an agent runs in the background;
3. a ChatGPT-like voice-to-voice surface that stays floating and drafts text for insertion.

Items **1 and 2 ship here**, verified by tests. Item 3 is not in this build and is **not** advertised anywhere
in the app — see "What is deliberately not in this build" below for the honest line.

---

## 1. SIMs: which SIM, whose number, and aiming a call

### New code

| File | What it is |
|---|---|
| `device/SimCore.kt` | Pure. Turns `SubscriptionInfo` rows into a decision + a Bengali/English sentence. |
| `device/DeviceAccess.kt` | The only place that touches `SubscriptionManager` / `TelecomManager` / `LauncherApps`. |

### What the user can now say

* **"সিম ২ দিয়ে রহিমকে ফোন করো"** — the SIM is parsed out of the sentence (`SimCore.parseSlot`: `সিম ২`,
  `২ নম্বর সিম`, `দ্বিতীয় সিম`, `sim 2`), the **name is not polluted** by the SIM words
  (`SimCore.stripSimPhrase`), the contact is resolved, and `TelecomManager.EXTRA_PHONE_ACCOUNT_HANDLE` is used
  to aim the call at that SIM's `PhoneAccountHandle`.
* **"আমার নম্বর কত" / "কয়টা সিম আছে"** → `sim.numbers`: each SIM with carrier, the system default-call SIM,
  and its own number **masked as `••••5678`** (a bubble can be screenshotted; the full number is never
  printed). With no `READ_PHONE_NUMBERS` the answer says exactly which permission to grant.
* **"কে ফোন করছে"** → `identity.who`: reads the live ringing notification, extracts the number, resolves it
  against the phone book, and answers *"রহিম ফোন করছে (কন্টাক্টে সেভ করা আছে)"* or
  *"অপরিচিত নম্বর 0155… ফোন করছে (সেভ করা নেই)"*, plus "ধরতে ‘ধরো’, কাটতে ‘কেটে দাও’ বলুন".
  When nothing is ringing it says so — it never invents a caller.

### The honest limit, stated in-app

Android does **not** expose "which internal call account belongs to SIM 2". `DeviceAccess.accountFor()` infers
it from the account label (`SIM 2`, carrier name) and then from slot position, and returns `null` when it
cannot. When that happens the call is still placed — on the system default SIM — and the bubble says:
*"…ঠিক কোন সিম দিয়ে যাবে নিশ্চিত করা যায়নি (reason); সিস্টেমের ডিফল্ট সিমে কল হচ্ছে।"* There is no silent
fallback and no false claim.

## 2. Chat instances: WhatsApp, WhatsApp Business, Dual Messenger clones

* `device/ChatInstanceCore.kt` — `ChatKind` (WhatsApp / WhatsApp Business / Messenger / Telegram / Signal /
  Viber), `ChatInstance(kind, package, userId, label, cloned, installed)` keyed by **`package@userId`**.
* Discovery uses **`LauncherApps.getActivityList(pkg, profile)` per `UserHandle`**, because a second WhatsApp
  ("Dual Messenger", a work profile) is a **second Android user**, invisible to `getInstalledPackages`.
  `UserManager.getSerialNumberForUser` ≠ 0 ⇒ `cloned = true`.
* **"বিজনেস হোয়াটসঅ্যাপ খোলো" / "ক্লোন করা হোয়াটসঅ্যাপ খোলো"** → opens that exact instance via
  `LauncherApps.startMainActivity(component, user, …)`.
* Ambiguity **asks**: `ChatInstanceCore.pick` narrows to the app named in the sentence, honours
  বিজনেস/business and ক্লোন/clone/দ্বিতীয়/dual/work/অফিস, and returns `null` when several remain — the bubble
  then lists the instances instead of guessing.
* A cloned instance **never** gets a direct-reply promise (`canDirectReply = false`) — its notifications are
  not reliably reachable from the owner profile.

## 3. Termux (and proot Ubuntu / OpenCode inside it)

* New permission row: `com.termux.permission.RUN_COMMAND` (+ `<queries><package android:name="com.termux"/>`).
* `DeviceAccess.runTermux()` dispatches through **`com.termux.app.RunCommandService`** with
  `com.termux.RUN_COMMAND`; nothing else is attempted, because nothing else can work.
* **`agents/TerminalPolicy.kt`** — the safety rule, pure and tested:
  * **off by default** (`AppSettings.termuxEnabled = false`) — a shell a microphone can reach is the most
    dangerous feature this app could ship;
  * read-only commands (`ls`, `pwd`, `termux-info`, `df -h`, `proot-distro list`, …) run without a card;
  * anything that can change the phone (`pkg install`, `rm`, `chmod`, redirects, `&&` …) asks **every time**;
  * `rm -rf /`, `mkfs`, `dd of=/dev/`, `reboot`, `curl | sh` … are **refused even when confirmed**.
* The app reports **"পাঠানো হলো"**, never "ran": output arrives in Termux, and Termux needs
  `allow-external-apps=true` in `~/.termux/termux.properties` — which the app explains and cannot set.
  proot-Ubuntu and OpenCode are reachable only *through* Termux, and the UI says so.

## 4. Background task board ("কাজ দাও: …")

* **"কাজ দাও: হোয়াটসঅ্যাপ খোলো; তারপর ক্যামেরা খোলো"** → a task with two steps; `;`, `তারপর`, `এরপর`, `then`,
  `।` and newlines all split steps (`TaskBoard.parseSteps`, max 8).
* **Design decision:** a step is an ordinary sentence handed to the *same* command pipeline a spoken command
  uses (`AssistantOverlayService.ACTION_RUN_TEXT` → offline grammar → model → confirmation → execution).
  Nothing is re-implemented, so **every permission, fallback and honest failure applies inside a task too**,
  and any future intent works in a task automatically. The runner owns only ordering, persistence, retry and
  reporting.
* `agents/TaskBoard.kt` — pure: `parseSteps`, `add` (max 20 tasks / 8 steps), `nextTask`, `recordStep`
  (**a failing step is retried once, then the task is marked FAILED** — never silently skipped), `cancel`,
  JSON encode/decode.
* `agents/TaskBoardStore.kt` — one small JSON file in `filesDir` (`tasks.json`); no Room migration needed.
* `agents/TaskRunner.kt` — sequential, in the app's process while the foreground bubble is alive; keeps the
  bubble up for the duration. A step that needs the user's confirmation and gets no answer within **90 s**
  leaves the task **PAUSED** with a Bengali note instead of being marked done.
* Settings → **ডিভাইস অ্যাক্সেস / কাজের বোর্ড**: add a task with its instructions, run queued tasks, cancel
  the running one, see per-step ✓/✗ and the retry note. The bubble shows the result of each step as usual.
* New intents: `task.add` (destructive → confirms), `task.list`, `task.cancel` (confirms).

## 5. Wiring, permissions, settings

* New intents also: `sim.numbers`, `identity.who`, `chat.open`, `termux.run` (all registered, all available).
* New slots: `Slot.SIM`, `Slot.CHAT` (the pipeline's `when` over slots is exhaustive again, with question
  lines for both).
* Manifest: `READ_PHONE_NUMBERS` (runtime), `READ_BASIC_PHONE_STATE` (install-time), `com.termux.permission.RUN_COMMAND`,
  `<queries><package com.termux/>`. **`PermissionCatalog` rows were added for each of the three** — the v1.2.0
  manifest↔catalog audit test enforces both directions, so a declared-but-unexplained permission fails the build.
* New `Feature.SIM` / `Feature.TERMUX` so "why is this not working" has one answer in the permission matrix.
* New settings: `termuxEnabled` (false) and `taskUpdatesInBubble` (true). Old saved settings still load
  (defaults are used for missing keys).

## Behaviour that did **not** change

`call.place` without a SIM word behaves exactly as v1.2.1 (system default SIM, same four-step fallback chain
documented in `telecom/CallController.kt`). Confirmations, Fast Mode, undo, scheduled messages and search are
untouched. `SEND_SMS` is still not requested.

## What is deliberately not in this build

* **The ChatGPT-like voice-to-voice surface and the floating draft/insert card are NOT in v1.3.0.** The
  existing floating bubble, dictation and insert-on-command path are unchanged; the new full-screen voice
  conversation with a draft card is the next increment (v1.3.1). Nothing in the UI pretends otherwise.
* Accessibility-based **silent send** in third-party apps, YouTube caption summaries, calendar read/add, and
  social summaries remain later work (see `ROADMAP-v1.2-to-v1.4.md`).
* Voice-driven SIM selection inside WhatsApp's own call button is not possible (no public API); the assistant
  places the call through Telecom and says which SIM it used.
