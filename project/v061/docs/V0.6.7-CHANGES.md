# VoiceDock AI — v0.6.7 (versionCode 13)

**Theme: the bubble now tells you exactly why the AI is not working — and always answers something.**

v0.6.6 introduced the small dictation bubble. On the phone the AI actions (✨ tidy up, 💬 ask) looked
"not connected": tapping them produced a generic line saying an AI key was needed, even when a key
had been saved. That was a real bug in the bubble, not in the provider layer.

## 1. Why it looked disconnected

`AiSetup.ready(ctx)` only answers *yes/no*. It returns `false` for five completely different
situations, and v0.6.6 collapsed all five into one sentence ("an AI key is needed"):

| Actual state | v0.6.6 said | v0.6.7 says |
|---|---|---|
| No key stored at all | "AI key দরকার" | "Google Gemini-এর কোনো key নেই — সেটিংস → AI প্রোভাইডারে key দিন" |
| Key saved, **no model chosen** (very common after adding a key without tapping "Test") | "AI key দরকার" ❌ | "Google Gemini-এর মডেল বাছা হয়নি — সেটিংস → AI-তে ‘যাচাই’ চেপে মডেল বাছুন" |
| "Send to cloud AI" consent is off | "AI key দরকার" ❌ | "‘ক্লাউড AI-তে পাঠানোর অনুমতি’ বন্ধ — সেটিংস → AI-তে চালু করুন" |
| Local-only mode is on | "AI key দরকার" ❌ | "শুধু-লোকাল মোড চালু — …" |
| Paid provider while paid use is off | "AI key দরকার" ❌ | "OpenAI পেইড — ‘পেইড প্রোভাইডার অনুমতি’ চালু করুন বা ফ্রি key দিন" |

A second bug compounded it: when the request did fail, the bubble threw away the provider's own
explanation (`AiSetup.explain`) and printed a fixed "AI সংযোগ ব্যর্থ". The old full panel did show
the real reason, so the two surfaces disagreed about the same failure.

## 2. What changed

* **New `ai/AiReadiness.kt`** — `AiReadinessCore.decide(...)` picks the provider to blame (the first
  usable one wins; otherwise the first that actually holds a credential, which is the most
  informative) and `AiReadinessCore.message(...)` turns the reason code into one actionable sentence
  in Bangla or English. Pure code, 10 new unit tests, no Android types.
* **`AiSetup.readiness(ctx)` / `readinessText(ctx)` / `needsSetup(ctx)`** — thin Android-side wrappers
  that feed the policy results in.
* **The bubble** shows the precise sentence, and a **⚙** mini-action appears next to the other icons
  while a setup problem is showing; tapping it closes the bubble and opens Settings → AI.
* **💬 never dead-ends** — when no provider is usable, and also when a request fails mid-flight, the
  bubble shows an offline answer from the existing `LocalIntentRouter` plus the reason. The prompt to
  the model is unchanged, so nothing extra is sent anywhere.
* **✨** keeps the recognised text untouched on failure and now appends the provider's own error
  (`AiSetup.explain`) instead of a generic line.
* Provider label (`Gemini · gemini-2.0-flash`) is shown under a successful answer, so you can see
  which provider actually served it.

## 3. Nothing else changed

Insert, tidy-up, ask, copy, close, the window flags (non-focusable, wrap-content, ≤ 68 % width) and
the long-press fallback panel are exactly as in v0.6.6. No new permission. minSdk stays **26**.

## 5. How to check it on the phone (two minutes)

1. Settings → AI providers: make sure a key is saved **and** a model is chosen (tap "Test").
   Then: dictate, tap ✨ → the text is rewritten and the provider name appears.
2. Now switch **off** "Send to cloud AI" and dictate again, tap 💬 →
   the bubble must display "‘ক্লাউড AI-তে পাঠানোর অনুমতি’ বন্ধ …" with a **⚙** icon, and an offline
   answer below it. Tap ⚙ → Settings opens.
3. Empty the key field and repeat → "… কোনো key নেই …". Never the same sentence as case 2.
