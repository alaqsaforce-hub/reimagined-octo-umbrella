## ১. Android প্ল্যাটফর্মের সীমা (এগুলো কখনোই "ঠিক" হবে না)

## ২. Google / OAuth-এর সীমা

- **নিজের OAuth client লাগে** (Google Cloud Console-এ তৈরি)। না থাকলে অ্যাপ সৎভাবে `notSetUp` বলে।
- **টোকেন শুধু মেমরিতে** — অ্যাপ বন্ধ হলে মুছে যায়। টোকেন নিজে নিজে নবায়ন হয় না, তাই **রিস্টার্টের পরে
  আবার কানেক্ট করতে হয়**। (নিরাপত্তার জন্য ইচ্ছাকৃত; refresh token রাখলে সেটা ডিস্কে থাকত।)
- **একটাই টোকেন, একসাথে তিন স্কোপ** (Drive read, Gmail read, Calendar events) — শুধু calendar চাইলে
  আগের access হারাত, তাই এক consent-এ তিনটাই।
- **ক্যালেন্ডার: শুধু primary**, শুধু পড়া + নতুন ইভেন্ট। মোছা, বদলানো, attendees রাখা, recurring তৈরি,
  সেকেন্ডারি ক্যালেন্ডার, ইভেন্টের রিমাইন্ডার/পুশ নোটিফিকেশন — **কিছুই নেই**।
- **Gmail শুধু পড়া** (পাঠানো নেই), **Drive শুধু পড়া** (লেখা/আপলোড নেই)।
- **অ-যাচাইকৃত অ্যাপ**: Google-এর verification না থাকলে consent screen-এ "unverified app" সতর্কতা আসে;
  testing mode-এ ব্যবহারকারী-সীমা থাকে।

## ৩. AI-এর সীমা

- **নিজের API key দরকার** (Gemini/OpenAI/Claude/local server)। key না দিলে শুধু offline নিয়ম-ভিত্তিক কমান্ড চলে।
- **লোকাল মডেল** ডিভাইসের RAM/CPU-নির্ভর; ছোট মডেলে বাংলা উত্তরের মান কম, দীর্ঘ উত্তর ধীর।
- **ইন্টারনেট না থাকলে** AI উত্তর নেই; ক্যালেন্ডার/Gmail/Drive/search সবই থেমে যায় (সৎ এরর দেয়)।
- **অফলাইন ইন্টেন্ট পার্সার** শব্দ-ভিত্তিক: শব্দচয়ন খুব অচেনা হলে `UNKNOWN` → AI দিয়ে সুধরে বা প্রশ্ন করে।
- **কোটা/খরচ**: প্রদানকারীর rate limit (`http_429`) হলে অ্যাপ সেটাই বলে, চুপচাপ আবার চেষ্টা করে না।
- **হ্যালুসিনেশন guard** আছে (ট্রান্সক্রিপ্ট/সারাংশে "বানাবে না" প্রম্পট), কিন্তু **গ্যারান্টি নয়**।

## ৪. ভাষা ও কমান্ড বোঝার সীমা

- ইন্টেন্ট ৫৪টি; প্রতিটার জন্য নির্দিষ্ট শব্দ-প্যাটার্ন। **উপভাষা/আঞ্চলিক বানান** (যেমন "শুক্র" বদলে
  "শুক্রবার" ধরা হয়) সবসময় ধরা নাও পড়তে পারে — তখন উত্তরটা কোন তারিখ পড়েছে সেটা বলে দেয়, তাই ভুলটা
  চোখে পড়ে।
- **বাংলা `\b` কাজ করে না, `\d` বাংলা অঙ্ক ধরে না** — তাই অঙ্ক/শব্দ আলাদা করে হ্যান্ডল করা হয়।
- UI ও উত্তর **দুই ভাষায় (বাংলা/ইংরেজি)**; তৃতীয় ভাষা নেই।
- **RTL/হিন্দি/উর্দু** সমর্থিত নয়।

## ৫. ডেটা, গোপনীয়তা ও ব্যাকআপ

- **API key / টোকেন**: Android Keystore-এ AES-256-GCM দিয়ে এনক্রিপ্ট করা (`SecretStore`) — ভালো।
- **সেটিংস ও নন-সিক্রেট**: সাধারণ SharedPreferences (এনক্রিপ্টেড নয়)।
- **ডেটাবেস (চ্যাট/মেমোরি/টাস্ক) এনক্রিপ্টেড নয়** — ডিভাইসে root থাকলে পড়া সম্ভব।
- **ব্যাকআপ/এক্সপোর্ট** আংশিক (BackupSection আছে), কিন্তু **এন্ড-টু-এন্ড এনক্রিপ্টেড ক্লাউড ব্যাকআপ নেই**।
- **Accessibility service-এর ক্ষমতা ব্যাপক** — এটি চালু থাকলে অ্যাপ তাত্ত্বিকভাবে যা দেখছে তা পড়তে পারে;
  কোডে গার্ড আছে (প্যাকেজ মিল, পাসওয়ার্ড বাদ), কিন্তু ব্যবহারকারীর সচেতন সিদ্ধান্ত দরকার।

## ৬. বিল্ড, টেস্ট ও ডিস্ট্রিবিউশন (আজকের বাস্তব সীমা)

- **APK debug-signed** — Play-র জন্য release keystore/Play App Signing লাগবে; sideload করলে Play Protect
  সতর্কতা দিতে পারে।
- **শুধু ইউনিট টেস্ট চলে** (৫২০টি, JVM)। **ইনস্ট্রুমেন্টেড/এমুলেটর টেস্ট এই পরিবেশে চলে না।**
- **আমি কোনো আসল ফোনে অ্যাপ চালাইনি** — সব ডিভাইস-আচরণ `docs/MANUAL-TESTS-v0.6.md`-এ আপনার জন্য
  চেকলিস্ট, আমার দাবি নয়।
- **CI নেই**; প্রতিবার /opt toolchain নতুন করে বসাতে হয় (`toolchain.sh`), বিল্ড মেমরি-সীমিত
  (`-Xmx1400m`, `--max-workers=1`) → একটি ফুল বিল্ড ৩–৭ মিনিট।
- **কোনো অটো-আপডেট নেই**; নতুন APK নিজে ইনস্টল করতে হয়।
- **minSdk 26** (Android 8+) — পুরোনো ফোনে চলবে না; **targetSdk 35**।
- **নেটিভ lib**: 16 KB page alignment যাচাই করা (Android 15+ requirement)।

## ৮. স্যান্ডবক্স/ওয়ার্কস্পেসের সীমা (এটা আপনার প্রশ্নের অংশ)

- **কোড শুধু এই ওয়ার্কস্পেসে**: `/home/user/repo` (git, HEAD `bf8d1df`)। **Google Drive-এ v0.6.0-এর পরে
  কিছু নেই**, GitHub-এ **v0.6.3-এর পরে কিছু নেই** — কারণ sandbox-এ **কোনো GitHub credential নেই**
  (কোনো PAT, SSH key বা `gh` CLI নেই; আর credential ফাইল snapshot থেকে ইচ্ছাকৃতভাবে বাদ যায়)।
- **`/opt` প্রতি টার্নে মুছে যায়** (JDK/SDK/Gradle আবার বসাতে হয়) — তাই বিল্ড ধীর।
- **snapshot সীমা** ~১২৮ MB / ১০,০০০ ফাইল; বিল্ড ফোল্ডার বাদ যায় — তাই প্রতিবার `app/build` prune করা হয়।
- **একাধিক APK রাখা হয় না** (ডিস্ক বাঁচাতে শুধু সর্বশেষটা `artifacts/`-এ)।
